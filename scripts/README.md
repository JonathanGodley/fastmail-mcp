# Scripts

Developer tooling. None of it ships with the server; `dist/` is built from `src/` alone.

| Script | What it does |
| --- | --- |
| `run-tests.mjs` | What `npm test` runs: `tsx --test` over the files given, killed with every process under it, exiting 1, if it has not ended within `TEST_RUN_LIMIT_MS` (default 600000; the suite takes under a minute). Exit code and output are the runner's otherwise. Off Windows, a SIGKILL to this process leaves the run going. |
| `kill-tree.mjs` | `killTree(child)` kills a spawned process and everything under it (a process group off Windows, `taskkill /T` on Windows); `run-tests.mjs` and `run-levers.mjs` use it. |
| `mcp-harness.mjs` | Raw JSON-RPC client that spawns `dist/index.js` as a real MCP server. `createClient({ env })` → `init`/`call`/`close`, matching responses by JSON-RPC `id`. `node scripts/mcp-harness.mjs --list` dumps the advertised tool schemas. Use it rather than hand-writing a client. |
| `scan-secrets.mjs` | The PII/credential scanner the git hooks run (`npm run scan:secrets` for a full sweep). See `CONTRIBUTING.md`. |
| `check-doc-links.mjs` | `npm run check:links` checks every relative link in `README.md`, `CONTRIBUTING.md`, `docs/*.md` and `docs/reference/*.md`: the file must exist, and a `#anchor` on a `.md` target must match a heading or an `<a name>`/`<a id>`. Exits 1 on a bad link. Its header lists what it does not handle. `src/check-doc-links.test.ts` runs it over the repo in `npm test`. |
| `vtimezone-scan.fuzz.mts` | An offline invariant sweep over the VTIMEZONE block scan behind #166 (`removeOrphanedVTimezones`, `regenerateVTimezones` in `src/caldav-client.ts`): needs no credentials, touches no network and does not use the built server. Run it with `npx tsx scripts/vtimezone-scan.fuzz.mts [iterations]` (default 200000). The invariant is described in its header and the mutations in its `MUTATE` list. Seeded, so a given count always generates the same payloads; exits non-zero on any violation or unexpected throw. Result on 25 Sep 2026, 200000 iterations: 337200 accepted, 62800 refused, 0 unexpected throws, 0 violations. |
| `payload-sizes.mts` | `npm run payload:sizes` measures five default tool results (`list_emails`, `get_email`, `get_thread`, `list_calendar_events`, `list_contacts`) in UTF-8 bytes and characters and prints each one's change against `src/testing/payload-sizes/baseline.json`. The payloads come from the real handlers and clients fed synthetic server data (`src/testing/payload-sizes/fixtures.ts`, whose header says what it represents); no credentials, no network. It never gates: it exits non-zero only when a payload cannot be produced or the baseline cannot be read. `-- --update` rewrites the baseline; run it in the commit that changes an output shape, and in a separate one when only the fixtures change, so each delta stays attributable. `src/payload-sizes.test.ts` runs the same measurement in `npm test` and prints the table without comparing it. |
| `comment-share.mjs` | `node scripts/comment-share.mjs <commit>` (or `--staged`, `--working`, `<a>..<b>`) says when a change added far more comment than the file it landed in carries - at least 20 comment lines at twice the file's own comment-per-code ratio. The pre-commit hook prints it; it never gates. Quiet unless something is over the bar; `--all` prints every measured file. |
| `find-raw-interpolations.mjs` | `node scripts/find-raw-interpolations.mjs [dir]` lists every `'${...}'` under `src/` rendered with no echo helper — the untrusted-values-in-prose class that the `echo-quoting convention` guard in `src/coerce.test.ts` provably **cannot** cover, because whether a value is untrusted depends on where it came from and nothing lexical separates the two. A hand-run inventory, not a test: the output is candidates to trace, never a defect list, and it always exits 0. |
| `mutation-test.mjs` | `npm run mutation -- <commit>` (or `--all`) runs Stryker mutation testing over the `src/` lines a commit changed, or all of `src/`, and prints Stryker's summary; survivors are untested lines. `--base <ref>` covers every `src/` line changed between the merge base of `<ref>` and `HEAD`, and `HEAD`, so a branch of several commits is measured whole. `--all --shard <i>/<n>` runs one size-balanced shard. Every mode writes a json report listing each mutant's status, errored ones included: `reports/mutation-commit.json` for a commit or `--base`, `reports/mutation.json` for `--all`, and `reports/mutation-<i>-of-<n>.json` for a shard, which alone also writes an html report beside it. From a git worktree it uses the primary checkout's `node_modules`. See `CONTRIBUTING.md`. |
| `mutation-summary.mjs` | `node scripts/mutation-summary.mjs reports/mutation-*.json` prints Markdown totals, the score and the surviving mutants (capped at 200) from one or more shard reports. The weekly mutation workflow writes its output to the run summary. |
| `run-levers.mjs` | `node scripts/run-levers.mjs levers.json` proves test pins by lever (CLAUDE.md, "Building and testing, in practice"). The file is an array of `{ label, target, find, replace, test, pattern, timeoutMs? }`; for each lever it swaps the one occurrence of `find` in `target`, runs the one `test` file under `tsx --test` filtered by `pattern` (a regular expression, passed to `--test-name-pattern`), and puts the original bytes back, also on timeout and on SIGINT, SIGTERM or SIGHUP. Prints one line per lever for the commit message: RED with the test whose assertion failed and that assertion's file:line, GREEN, THREW (the test failed by a throw that is not an assertion), TIMEOUT (default 300000 ms), or INVALID with the reason (`find` not there exactly once, no test matched before or after the lever, the test fails without the lever, or no test failed at a line in the repo, as when the lever stops the file loading). Exits non-zero unless every lever is RED. It refuses to start while `git status` shows a change to a target; a gitignored target is not refused, though the restore still writes back the bytes it read. SIGKILL or a crash can leave a target modified, and the next run then refuses until it is restored. |
| `dump-official-surface.mjs` | Snapshots Fastmail's official MCP tool surface into `docs/official-mcp-*`, for comparing it with this server's tools. The output is deliberately not committed; the generator is. |
| `probes/` | On-demand live checks against a real account. See `probes/README.md` — they are not regression coverage, and some of them send mail. |
